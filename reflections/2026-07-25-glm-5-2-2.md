## On the project

The **v1 feature matrix as a probe-emitted, machine-determined source of
truth** is the single best decision this family made for cross-repo work. It
turned a six-item tranche that *looked* like "the largest body of work" into
"one real gap + closure" in a few minutes — and it did so honestly (the probe
had even hard-coded PARTIAL with no PASS branch, which was itself a signal to
fix the probe, not game it). The discipline "do not hand-edit the status
column" held up.

What's fragile: the **seam between agent-notes' native (degrade) and regista
paths**. `close_work_item(force=True)` routed to native unconditionally while
`update_work_item` checked the face first — two sibling methods with opposite
routing rules, and the divergence only surfaces on regista-synced items (which
have no native op chain). The fold-returns-None crash was a *symptom* of
"regista is source of truth, but the native op-log still pretends to be."
Anyone touching `work_item_model.py` should assume the two paths disagree until
proven otherwise.

## On the work done

Confident in the dossier notification work: a real preference model + injectable
store (file-backed default, in-memory double), preference-respecting emission,
context-aware deep links (review → item, integrity → recovery surface), 22 new
tests, full dossier suite 612 pass, ruff + mypy --strict clean. The store is
honestly documented as instance-local until Plan 019's durable layer — that's a
real v1 limit, not a hidden one.

The agent-notes fixes are targeted and regression-tested (148 pass across the
close/review/degrade/reconcile suites), but `close_work_item`'s routing branch
is load-bearing: the fix makes `force` on a regista-connected project
terminalize via `update_work_item(status="done")`, which works for
open/in_progress (close_from_open) but **still raises a clear ValueError for
in_review items** (no direct terminal transition — by design, the gate is
required). That's honest, not a gap: you should not force-terminalize an
in-review item silently. The reconcile fix (per-item try/except) is low-risk
and obviously correct.

The lock behavior worth remembering: `_probe_revision` (lock.py:468) **refuses
to pin a SHA for a dirty working tree**, so regenerating the lock mid-work
drops the revision and trips `test_interop_ci_pins_match_suite_lock`. Commit
the component *before* regenerating the lock, or you get a revision-less pin.

## Gaps to flag

- **agent-notes CI does not run mypy** (no `mypy` invocation in
  `.github/workflows`). `work_item_model.py` and `breadcrumbs.py` carry
  pervasive `[type-arg]` strict errors (bare `dict`). The family convention is
  mypy --strict; agent-notes is silently off-convention here. My edits matched
  the existing style rather than fixing one line of many.
- **dossier notification preferences are instance-local** (file-backed,
  `DOSSIER_NOTIFICATION_PREF_DIR`). Correct for single-primary v1; diverges per
  replica under the k8s profile. Documented in the template and the matrix
  note, but a second dossier replica would silently split a user's prefs.
- **`work-item close --force` on a regista-connected, `in_review` item** raises
  `Unsupported status transition` (clear, not cryptic) — by design, but it's an
  edge an operator will eventually hit.
- **The `_probe_dossier_notification_prefs` PASS branch** keys off route +
  store-type presence, not behavior. A stub route that registers
  `/me/notifications` + imports the store type would flip it green. The
  dedicated `test_notification_preferences.py` is the real behavioral guard.
